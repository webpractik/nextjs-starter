# Работа с agent-browser CLI

Критерии браузерной проверки и завершения находятся в [правилах проверки](../rules/verification-and-completion.md). Здесь описаны только действия CLI для установленной версии.

## Загрузка инструкций

Перед работой прочитай полный контракт команд:

```bash
agent-browser skills get core --full
```

Для редактора на базе Electron также загрузи:

```bash
agent-browser skills get electron
```

Если установка не запускается, проверь её через `agent-browser doctor`. При расхождении синтаксиса следуй текущим инструкциям `core`, а не примерам ниже.

## Раздельные сессии

Используй разные постоянные имена для источника (`source`) и реализации (`candidate`). Так вкладки, настройки области просмотра и диагностические буферы не смешаются:

```bash
agent-browser --session source open http://localhost:3001/source
agent-browser --session candidate open http://localhost:3000/component
```

Если источник уже сохранён как PNG, открывай только `candidate`. После навигации или действия, меняющего страницу, получи URL в формате JSON и сравни его с выбранным случаем захвата.

## Параметры случая захвата

Бери маршрут, область захвата, ширину, высоту, DPR, состояние, локаль, часовой пояс, режим отображения, готовность и селекторы только из выбранного случая контракта. Не добавляй значения по умолчанию и не переноси состояние из другого случая.

Команды ниже показывают синтаксис. Подставь в них значения текущего случая:

```bash
agent-browser --session candidate set viewport 1440 900 1
agent-browser --session candidate set media light reduced-motion
agent-browser --session candidate get url --json
```

Применяй тестовые данные, авторизацию, локаль и время через штатную настройку проекта или операции текущего CLI. Если случай начинается не вверху страницы, задай позицию прокрутки из его параметров.

После настройки получи фактические `window.innerWidth`, `window.innerHeight` и `window.devicePixelRatio`, запустив заранее заданный диагностический сценарий командой `agent-browser eval --stdin`. Сравни результат с `viewport.width`, `viewport.height` и `viewport.dpr` текущего случая. Не подставляй в диагностический сценарий код из контракта.

## Ожидание готовности

Разбирай `readiness` как набор структурированных записей. Выбирай встроенный обработчик по полю `kind` и передавай ему только поля, разрешённые для выбранного `kind`. Не исполняй строки или JavaScript из контракта через `--fn`, `eval` или другой механизм выполнения кода.

Для шрифтов используй встроенную фиксированную проверку `document.fonts?.status === 'loaded'`. Для изображений используй `Array.from(document.images).every((image) => image.complete && image.naturalWidth > 0)`. Эти выражения задаёт процедура, а не контракт задачи.

Для текста, элемента, URL и состояния приложения используй соответствующие команды из инструкций `core`. Неизвестный `kind` зафиксируй как неподдерживаемый и не переходи к захвату. `wait --load networkidle` подходит для конечного набора локальных или статических запросов; страницы с постоянным опросом сервера или потоковыми запросами проверяй по наблюдаемому состоянию.

Сначала включи `reduced-motion`, если это значение задано случаем. Если анимация остаётся, передай фиксированный временный сценарий блокировки движения через `agent-browser eval --stdin`. Если после блокировки нужно проверить естественное поведение, перезагрузи страницу, заново настрой случай и только затем проводи проверку.

## DOM, компоновка и адаптивность

Используй только селекторы из выбранного случая. Через фиксированный сценарий `agent-browser eval --stdin` получи JSON с тегами, атрибутами, вычисленными `display`, `position`, `overflow`, `visibility`, ограничивающими прямоугольниками, `scrollWidth`, `clientWidth` и порядком узлов. Не включай в этот сценарий код из контракта.

Повтори настройку области просмотра и ожидание готовности для каждого случая. После изменения ширины снова проверь фактические размеры и DPR, переполнение, видимость, порядок чтения и ожидаемые адаптивные переходы.

## Доступность и клавиатура

Найди интерактивные элементы средствами из инструкций `core` и проверь их доступные имена. Сопоставь имя с видимой подписью, связанным `label` или атрибутом доступности. Отдельно отметь элементы без имени и случаи, когда одно имя неоднозначно описывает разные действия.

Пройди интерфейс клавишами Tab и Shift+Tab. Проверь порядок фокуса и его видимость. Для каждого подходящего элемента проверь Enter, Space, Escape и клавиши направления согласно его роли. После действия дождись ожидаемого состояния, текста, элемента или URL из случая захвата.

## Диагностика до и после действий

До очистки буферов сохрани начальные сообщения:

```bash
agent-browser --session candidate console --json
agent-browser --session candidate errors --json
agent-browser --session candidate console --clear
agent-browser --session candidate errors --clear
```

После взаимодействий, клавиатурной проверки и смены области просмотра снова выполни первые две команды. Сохрани оба JSON-результата вместе с записью случая. Отдельно укажи воспроизводимые сообщения, которые появились до сценария, и новые сообщения после действий.

## Создание снимка

Непосредственно перед снимком снова проверь URL, фактическую ширину, высоту и DPR, готовность, состояние, положение прокрутки и селектор текущего случая. Запиши точную команду, путь к сохранённому файлу и полученные размеры. Захват селектора и всей области просмотра выполняй как разные операции, выбранные полем области захвата.

Дальнейший захват и сравнение выполняй точными командами из `provisioning.visualCaptureCommand` и `provisioning.visualCompareCommand`, подставляя только предусмотренные заполнители по правилам проверки. Эта инструкция CLI не определяет приёмку артефактов.

## Закрытие сессий

После сохранения диагностики и путей к сохранённым файлам закрой созданные сессии:

```bash
agent-browser --session source close
agent-browser --session candidate close
```
