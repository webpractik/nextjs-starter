# Работа с Figma-коннектором

Условия доступа и приёмки находятся в [правилах источников и ресурсов](../rules/source-and-assets.md). Здесь описаны только действия в коннекторе и редакторе.

## Разбор URL

До записи проверь HTTPS-URL Figma: допустимы только хост `figma.com` или `www.figma.com`, стандартный порт и единственный параметр `node-id`; учётные данные, фрагмент, параметры доступа, сессии и отслеживания запрещены. Если переданный адрес содержит лишнее, примени `STOP` и запроси очищенную ссылку на тот же узел — не сохраняй и не пересказывай исходное значение. Из проверенного адреса извлеки ключ файла и `node-id`. Для адреса `/design/<fileKey>/branch/<branchKey>/...` передавай коннектору `branchKey` как ключ файла. В остальных поддерживаемых адресах используй `fileKey`. Для вызовов коннектора приведи `12-34` и `12:34` к форме `12:34`.

## Проверка доступных операций

Сначала изучи настроенный коннектор. Найди операции для контекста дизайна, метаданных, снимка узла, переменных, ресурсов, экспорта и Code Connect. Используй самую узкую операцию для выбранного узла.

Перед каждым вызовом проверь `design-context-manifest.json`. Ключ вызова состоит из `operation`, `fileKey` и `nodeId`. Если такая запись уже есть, прочитай сохранённый ответ вместо повторного запроса. В манифесте заполни `fileKey`, `fileVersion` и `rootNodeId`, а для каждого запроса сохрани `requestId`, `operation`, `responseFormat`, `nodeId`, `path` и `checksum`.

Формат и расширение зависят от операции:

- `get_design_context`: `responseFormat: "text"`, файл `.txt`.
- `get_metadata`: `responseFormat: "xml"`, файл `.xml`.
- `get_screenshot`: `responseFormat: "png"`, файл `.png`.
- `get_variable_defs`, `download_assets`, `get_code_connect_map`: `responseFormat: "json"`, файл `.json`.

## Адаптивный сбор контекста

Собирай контекст в таком порядке:

1. Вызови `get_design_context` для точного узла из URL.
2. Сохрани полный текстовый ответ без преобразований в `.txt` и добавь его путь, `responseFormat: "text"` и SHA-256 в `artifacts/visual/<task-id>/design-context-manifest.json` до анализа содержимого.
3. Если ответ полный, используй его на следующих этапах.
4. Если ответ слишком велик или усечён, не повторяй тот же вызов. Один раз вызови `get_metadata` для исходного узла и сохрани ответ в манифесте.
5. По метаданным выбери только дочерние узлы, которые входят в область задачи. Для каждого из них один раз вызови `get_design_context`, затем сохрани исходный текстовый ответ, `responseFormat` и его SHA-256.

Не переходи к соседнему узлу или родительскому фрейму, чтобы обойти ограничение размера. Не повторяй одну и ту же тройку `operation` + `fileKey` + `nodeId`, даже после сокращения истории беседы.

Из сохранённых ответов перенеси в сведения до начала реализации доступные данные:

- иерархию, порядок наложения, видимость, обрезку, маски и абсолютные границы;
- компоновку, размеры, ограничения, перенос, выравнивание, внутренние отступы и промежутки;
- текст и метрики шрифтов;
- заливки, обводки, непрозрачность, радиусы, эффекты и фоны;
- переменные, стили, активные режимы, псевдонимы и разрешённые значения;
- компоненты и экземпляры, варианты, свойства, переопределения и состояния;
- заливки изображением, режимы `crop/scale`, векторную геометрию, настройки экспорта и идентификаторы ресурсов;
- ссылки прототипа и метаданные взаимодействий.

Помечай данные коннектора как `observed`, выводы об иерархии и ограничениях как `inferred`, а недоступные значения как `unknown`. Не вычисляй размеры по усечённому ответу.

## Дополнительные данные

Если коннектор поддерживает нужную операцию, вызови `get_screenshot` для точного исходного узла. Ответ содержит PNG как встроенные данные или URL, в зависимости от клиента. Сразу сохрани точные байты, размеры и SHA-256; при ответе с URL сначала загрузи файл. Запроси `get_variable_defs` для используемых переменных. После `download_assets` сразу загрузи найденные ресурсы и вычисли их SHA-256. Сам ответ с временными URL в проект не записывай: создай очищенную JSON-запись без URL и учётных данных по правилам [`source-and-assets.md`](../rules/source-and-assets.md). Если клиент временно записал исходный ответ на диск, удали файл после загрузки ресурсов.

Если доступна операция `get_code_connect_map`, получи сопоставления Code Connect для исходного и выбранных дочерних узлов. Сохрани каждый ответ и его SHA-256 в манифесте. Рассматривай сопоставление как подсказку к поиску компонента в проекте, а решение о повторном использовании принимай по правилам реализации.

## Экспорт узла и ресурсов

Используй PNG из `get_screenshot` для растрового эталона. SVG выбирай, когда `download_assets` возвращает исходный векторный экспорт узла; временный ответ замени очищенной записью по правилам выше. PDF в этот пакет не передавай. Вместе с байтами запиши логические границы, масштаб, размер в пикселях, фон или прозрачность, активный режим или вариант и параметры экспорта.

Вычисли SHA-256 загруженных байтов до просмотра или преобразования. Сохрани экспорт и метаданные по правилам источников: назначь пути и опиши происхождение растеризации.

Для изображений и векторов, которые войдут в реализацию, экспортируй ресурсы по настройкам соответствующих узлов или слоёв. Сохрани прозрачность, масштаб и параметры обрезки, чтобы локальный файл воспроизводил отрисовку Figma.

## Резервный путь через редактор

Если структурированный экспорт недоступен, но авторизованный редактор открывает файл, создай отдельную браузерную сессию и перейди к тому же нормализованному узлу. Для настольного редактора сначала прочитай инструкции браузера `core`, затем инструкции Electron. Запиши имя узла, цепочку родительских узлов, границы, вариант или режим, масштаб редактора, положение холста и видимое состояние интерфейса.

Перед экспортом изолируй узел и сверь его ID и границы с сохранёнными метаданными. Считай снимок редактора диагностикой, пока изолированный экспорт не пройдёт проверку по правилам источников. Команды браузера описаны в [`agent-browser-cli.md`](./agent-browser-cli.md).

## Экспорт от пользователя

Для полученного PNG или SVG запиши имя, размер файла в байтах, геометрические размеры, формат, SHA-256, заявленный ID узла и точный URL Figma. Сохрани исходные байты и зафиксируй их происхождение по тем же правилам, что и для результата коннектора.

## Передача результата

Передай исходный URL, ключ файла, ID узла и `design-context-manifest.json` со всеми путями и контрольными суммами. Добавь использованные операции, метаданные узлов, параметры экспорта, обнаруженные шрифты, переменные, ресурсы, сопоставления Code Connect и реестр `observed`/`inferred`/`unknown`. Допустимость источника и причины `STOP` определяй по [`source-and-assets.md`](../rules/source-and-assets.md).
