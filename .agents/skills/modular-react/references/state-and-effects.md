<a id="владение-state"></a>

## Владение состоянием

| Состояние | Владелец |
| --- | --- |
| Временное состояние UI | useState/useReducer |
| URL и навигация | Роутер проекта |
| Серверные данные | TanStack Query |
| Общее клиентское состояние внешнего менеджера | Независимое от фреймворка хранилище и useSyncExternalStore |
| Состояние возможностей браузера | Браузер; хук react-use адаптирует его для React |
| Стабильные зависимости и конфигурация | Context |

Состояние TanStack Query не дублируется в локальном состоянии, Context или
внешнем хранилище. Ключи, кэш, мутации, предзагрузка и гидратация принадлежат
`tanstack-query`. Context передаёт только стабильные зависимости и конфигурацию,
включая экземпляр хранилища; изменяемое состояние запрещено.

Основной и альтернативный каналы любого менеджера общего внешнего клиентского
состояния проходят через единый независимый от фреймворка контракт и хук модуля
на useSyncExternalStore. Прямые хуки менеджера из компонентов запрещены.
Кэш Query и вспомогательные хуки react-use исключены; последние адаптируют
состояние браузера, сохраняя его владельца.

<a id="контракт-external-store"></a>

## Контракт внешнего хранилища

```typescript
import { useSyncExternalStore } from 'react'

export interface ExternalStore<TSnapshot, TCommands> {
  getSnapshot(): TSnapshot
  subscribe(listener: () => void): () => void
  readonly commands: TCommands
  getServerSnapshot?(): TSnapshot
}

export function useFeatureSnapshot<TSnapshot, TCommands>(
  store: ExternalStore<TSnapshot, TCommands>,
): TSnapshot {
  return useSyncExternalStore(
    store.subscribe,
    store.getSnapshot,
    store.getServerSnapshot,
  )
}
```

Снимок неизменяем и сохраняет ссылочную идентичность до изменения данных.
`subscribe` возвращает функцию отписки. Хранилище меняется через явные
типизированные `commands`, без изменения снимка. Функции контракта и commands
стабильны по ссылке и не зависят от потерянного `this`. Данные запроса не хранятся
в общем состоянии процесса.

В CSR `getServerSnapshot` необязателен. В SSR его снимок совпадает с первым
клиентским снимком.

## CSR, SSR и RSC

В CSR используйте subscribe/getSnapshot без дублирования состояния;
getServerSnapshot необязателен. В SSR он обязателен и совпадает с первым
клиентским снимком для детерминированной гидратации.

useSyncExternalStore работает только в клиентском модуле; Server Components
не подписываются на клиентское хранилище. Начальная конфигурация сериализуема,
серверные зависимости недоступны из клиентского графа. Хранилище с данными
запроса изолировано между запросами.

## Политика react-use

react-use допустим для вспомогательных функций браузера и UI: медиазапросов,
измерений, буфера обмена, видимости. Он не заменяет менеджер состояния, загрузку
данных или бизнес-процесс; состоянием владеет браузер, хук его адаптирует.
Проверьте типизированный прямой импорт либо проектный optimizePackageImports
и жизненный цикл для выбранного CSR/SSR/RSC. Внутренний импорт с неявным any
запрещён.

## Лестница решений перед Effect

1. Вычислите значение при рендере.
2. Выполните действие в обработчике события.
3. Передайте серверное состояние TanStack Query.
4. Подключите общее клиентское состояние внешнего менеджера через
   useSyncExternalStore.
5. Используйте Effect только для синхронизации внешней системы.

## Допустимый Effect

Effect называет внешнюю систему и синхронизирует подписку, таймер, императивный
DOM или сторонний виджет. Он идемпотентен, переживает повторное монтирование в
Strict Mode, указывает все зависимости и не принимает доменных решений.

Если настройка создаёт подписку, таймер, соединение, другую отменяемую операцию
или освобождаемый ресурс, Effect симметрично очищает их. Для идемпотентной
синхронизации только записью без захвата ресурса явно обоснуйте отсутствие
очистки.

<a id="запрещённые-effect-patterns"></a>

## Запрещённые шаблоны Effects

- useEffect без названной внешней системы.
- Производное состояние или синхронизация состояния с props.
- Действие по событию через состояние и Effect.
- Ручная загрузка вместо TanStack Query.
- Валидация, права доступа, ценообразование или бизнес-процесс.
- Подписка на хранилище через useState + Effect вместо useSyncExternalStore.

<a id="граница-view"></a>

## Граница представления

Представление отвечает за JSX, доступность, форматирование готовой модели,
временное состояние UI, фокус, выделение и передачу событий. Доменные правила,
авторизация, цены, допустимость действий, нормализация, преобразование DTO и
координация сценариев остаются в domain/application/infrastructure.

Хук-контроллер адаптирует обработчики и статусы, не принимая бизнес-решений.
При сложном процессе определите
[состояния и допустимые переходы](application-contracts.md#состояния-процесса).
Отдельный автомат процесса не должен дублировать состояние Query; доменные
переходы проверяет модель, доступные действия отображает UI.

## Контрольный список

- [ ] У каждого состояния один владелец; состояние Query не дублируется.
- [ ] Внешнее хранилище соблюдает контракт subscribe/getSnapshot/commands и
  предоставляет getServerSnapshot для SSR.
- [ ] Каждый Effect прошёл лестницу решений и освобождает созданные ресурсы или
  отменяет операции, если они допускают отмену.
- [ ] Представление получает готовые данные и обработчики.
